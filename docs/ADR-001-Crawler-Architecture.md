# ADR-001: UTC/UTC2 Crawler Architecture

**Status**: Proposed  
**Date**: 2026-11-20  
**Decision Makers**: Technical Team  
**Stakeholders**: Product Owner, DevOps, QA

## Context

Hệ thống UTC RAG Chatbot cần crawler tự động thu thập và đồng bộ dữ liệu tuyển sinh từ utc.edu.vn và utc2.edu.vn vào PostgreSQL/pgvector. Crawler phải chạy theo lịch, phát hiện thay đổi, tránh trùng lặp, và hỗ trợ recovery khi crash.

Database schema hiện tại đã có:
- `crawl_sources`: Quản lý nguồn crawl
- `crawl_jobs`: Quản lý job crawl
- `knowledge_documents`: Tài liệu canonical
- `document_revisions`: Các phiên bản tài liệu
- `document_chunks`: Chunks đã embedding

Backend đã có:
- API tạo crawl job (TECH_OPERATOR role)
- API upload PDF với hash SHA-256 từ bytes
- Publication workflow với reviewer approval
- RAG query chỉ truy vấn `status='PUBLISHED' AND source_verified AND revoked_at IS NULL`

Tools hiện tại: Chỉ có placeholder, chưa implementation.

**Phân tích**:
- Schema không có CHECK constraint cho status
- Unique index chỉ ngăn duplicate job với status PENDING/RUNNING
- Có `lease_until`, `claim_token`, `attempt_no` nhưng chưa được sử dụng (đã verify không có code nào đọc/ghi các cột này)
- Backend chỉ tạo job với `status='PENDING'` và check duplicate bằng query `findAllBySourceIdAndStatusIn(source, ["PENDING", "RUNNING"])`

**File**: `backend/src/main/java/vn/edu/utc/rag/service/ingestion/OpsService.java` (line 113)
```java
entity.setStatus("PENDING");
```

### Decision

**State Machine cho `crawl_jobs`**:

```
PENDING → RUNNING → COMPLETED
                  ↘ FAILED
```

**Trạng thái**:
- `PENDING`: Job mới tạo, chưa được claim
- `RUNNING`: Job đã được worker claim và đang xử lý
- `COMPLETED`: Job hoàn thành thành công (thêm mới)
- `FAILED`: Job thất bại sau max_attempts (thêm mới)

**Lý do chọn COMPLETED thay vì DONE**:
- Nhất quán với domain language (personality_attempts dùng COMPLETED)
- Rõ nghĩa hơn DONE (có thể nhầm với boolean flag)
- Phân biệt rõ với FAILED

**Lease-based Claiming Mechanism**:

```python
# Worker claim job atomically
UPDATE crawl_jobs 
SET status = 'RUNNING',
    lease_until = NOW() + INTERVAL '10 minutes',
    claim_token = gen_random_uuid(),
    attempt_no = attempt_no + 1
WHERE id = (
    SELECT id FROM crawl_jobs
    WHERE status = 'PENDING' 
      AND run_after <= NOW()
    ORDER BY run_after, id
    LIMIT 1
    FOR UPDATE SKIP LOCKED
)
RETURNING *;
```

**Heartbeat Mechanism**:
```python
# Worker extends lease every 3 minutes
UPDATE crawl_jobs
SET lease_until = NOW() + INTERVAL '10 minutes'
WHERE id = :job_id 
  AND claim_token = :token
  AND status = 'RUNNING';
```

**Expired Lease Recovery**:
```python
# Scheduler or separate recovery process
UPDATE crawl_jobs
SET status = 'PENDING',
    lease_until = NULL,
    claim_token = NULL
WHERE status = 'RUNNING'
  AND lease_until < NOW()
  AND attempt_no < 5;  -- Max retries

-- Mark as FAILED if max attempts reached
UPDATE crawl_jobs
SET status = 'FAILED'
WHERE status = 'RUNNING'
  AND lease_until < NOW()
  AND attempt_no >= 5;
```

**Job Completion**:
```python
# Worker completes job
UPDATE crawl_jobs
SET status = 'COMPLETED',
    completed_at = NOW(),
    lease_until = NULL,
    claim_token = NULL
WHERE id = :job_id
  AND claim_token = :token
  AND status = 'RUNNING';
```

**Job Failure**:
```python
# Worker reports failure
UPDATE crawl_jobs
SET status = 'FAILED',
    completed_at = NOW(),
    error_message = :error,
    lease_until = NULL,
    claim_token = NULL
WHERE id = :job_id
  AND claim_token = :token
  AND status = 'RUNNING';
```

**Exponential Backoff**:
```python
run_after = NOW() + INTERVAL '1 minute' * POWER(2, attempt_no)
# attempt 0: immediate
# attempt 1: 2 min
# attempt 2: 4 min
# attempt 3: 8 min
# attempt 4: 16 min
```

### Scheduler Design

**Decision**: Scheduler tạo job qua **Backend API** (`POST /api/v1/ops/crawl-jobs`)

**Lý do**:
- Backend đã có logic check duplicate (findAllBySourceIdAndStatusIn)
- Backend đã có audit log (record CREATE_JOB)
- Backend đã có rate limiting (10 req/min)
- Backend đã có authentication/authorization (TECH_OPERATOR)
- Nhất quán với security model
- Dễ test và monitor

**Scheduler Implementation**:
- Scheduler là Python script riêng (không phải worker)
- Chạy theo cron schedule (ví dụ: mỗi 6 giờ)
- Gọi Backend API với service account credentials
- Tạo job cho từng source enabled
- Log kết quả vào stdout để Docker capture

**Phân loại**: **Đề xuất kỹ thuật** (nhất quán với kiến trúc hiện tại)

## Decision 2: Document Indexing State Machine

### Xác nhận từ Source Code

**File**: `backend/src/main/java/vn/edu/utc/rag/service/ingestion/DocumentService.java` (line 268)
```java

e.setStatus("PUBLISHED"); // line 335
e.setStatus("REVOKED");   // line 368
```

**File**: `database/init/002-schema.sql` (line 493)
```sql
UNIQUE (document_id, content_hash, pipeline_key, embedding_model)
```

**Phân tích**:
- Backend tạo revision với `status='INDEXING'`
- Backend KHÔNG có code chuyển INDEXING → PENDING
- Backend có thể publish revision với status PENDING/PUBLISHED/ARCHIVED
- UNIQUE constraint ngăn duplicate nhưng không có logic xử lý collision
- Không có cơ chế verify revision đã hoàn thành indexing

### Decision

**State Machine cho `document_revisions`**:

```
INDEXING → PENDING → PUBLISHED → ARCHIVED
                   ↘           ↗
                     (reviewer rejects, stays PENDING)

Any state → REVOKED (by reviewer, permanent)
```

**Trạng thái**:
- `INDEXING`: Revision đang được worker tạo chunks và embedding
- `PENDING`: Revision đã có đủ chunks, chờ reviewer approve
- `PUBLISHED`: Revision được verify và publish, xuất hiện trong RAG
- `ARCHIVED`: Revision cũ bị thay thế bởi PUBLISHED mới
- `REVOKED`: Revision bị thu hồi (sai thông tin, vi phạm chính sách)

**Transition Rules**:
- Worker: `INDEXING → PENDING` (sau khi hoàn tất chunks)
- Reviewer: `PENDING → PUBLISHED` (approval + source_verified=true)
- System: `PUBLISHED → ARCHIVED` (khi publish revision mới)
- Reviewer: `* → REVOKED` (manual action)

### Recovery và Idempotency

**Problem**: Worker crash giữa chừng indexing

**Solution 1: Chunk Count Verification**
```python
# Before updating to PENDING, verify chunks exist
SELECT COUNT(*) FROM document_chunks WHERE revision_id = :rev_id;

# Only update if count > 0
UPDATE document_revisions
SET status = 'PENDING', updated_at = NOW()
WHERE id = :rev_id 
  AND status = 'INDEXING'
  AND EXISTS(SELECT 1 FROM document_chunks WHERE revision_id = :rev_id);
```

**Solution 2: Idempotent Processing**
```python
# Worker workflow
def process_document(job_id, url, content):
    # 1. Hash content
    content_hash = sha256(extracted_text).hexdigest()
    
    # 2. Check existing revision
    existing = db.query("""
        SELECT id, status FROM document_revisions
        WHERE document_id = :doc_id
          AND content_hash = :hash
          AND pipeline_key = :pipeline
          AND embedding_model = :model
    """, {...})
    
    if existing:
        if existing['status'] == 'PENDING':
            # Already completed, idempotent
            return existing['id']
        elif existing['status'] == 'INDEXING':
            # Reuse and continue
            revision_id = existing['id']
            # Delete partial chunks if any
            db.execute("DELETE FROM document_chunks WHERE revision_id = :id", id=revision_id)
        else:
            # PUBLISHED/ARCHIVED: skip, content unchanged
            return existing['id']
    else:
        # 3. Create new revision (INSERT or get from UniqueViolation)
        try:
            revision_id = create_revision(...)  # status='INDEXING'
        except psycopg.errors.UniqueViolation:
            # Another worker just created it, requery
            existing = db.query(...)
            return process_document(...)  # Retry
    
    # 4. Chunk and embed
    chunks = chunk_text(extracted_text)
    for i, chunk in enumerate(chunks):
        embedding = call_ollama_embed(chunk)
        db.execute("""
            INSERT INTO document_chunks (revision_id, position, body, locator, embedding)
            VALUES (:rev, :pos, :body, :loc, :emb)
            ON CONFLICT (revision_id, position) DO UPDATE
            SET body = EXCLUDED.body, embedding = EXCLUDED.embedding
        """, {...})
    
    # 5. Mark as PENDING
    db.execute("""
        UPDATE document_revisions
        SET status = 'PENDING', updated_at = NOW()
        WHERE id = :id AND status = 'INDEXING'
    """, id=revision_id)
    
    return revision_id
```

**Solution 3: Stuck INDEXING Detection**
```python
# Monitor dashboard query
SELECT id, title, official_url, updated_at, 
       NOW() - updated_at AS stuck_duration
FROM document_revisions
WHERE status = 'INDEXING'
  AND updated_at < NOW() - INTERVAL '1 hour'
ORDER BY updated_at;
```

**Transaction Boundaries**:
- Revision creation: Single transaction
- Chunk insertion: Batch per 100 chunks (với ON CONFLICT)
- Status update to PENDING: Single transaction after all chunks committed

**Phân loại**: **Đề xuất kỹ thuật**

## Decision 3: Backend vs PostgreSQL Boundary

### Comparison Matrix

| Aspect | A. Direct PostgreSQL | B. Backend API |
|--------|---------------------|----------------|
| **Authentication** | PostgreSQL role `utc_worker` | Service account JWT |
| **Authorization** | GRANT specific tables | Backend role check (TECH_OPERATOR) |
| **Audit Log** | Manual INSERT audit_events | Automatic via audit.record() |
| **Validation** | Python code | Backend validation + constraints |
| **Transaction** | psycopg transaction | @Transactional |
| **Atomic Claim** | SELECT FOR UPDATE SKIP LOCKED | Would need new API endpoint |
| **Bulk Insert** | psycopg executemany() | Would need batch API |
| **Concurrency** | PostgreSQL locks | Backend transactions |
| **Maintainability** | Duplicate SQL logic | Centralized in Backend |
| **Testing** | Integration tests needed | Can unit test Backend |

### Decision

**Choice**: **A. Python worker thao tác PostgreSQL trực tiếp**

**Rationale**:

**Pros of Direct PostgreSQL**:
1. **Atomic Job Claiming**: `SELECT FOR UPDATE SKIP LOCKED` không thể implement qua REST API
2. **Bulk Operations**: Insert 1000+ chunks per document, REST overhead không chấp nhận được
3. **Performance**: Embedding 1 doc = ~100-500 chunks, REST = 100-500 requests vs 1 batch query
4. **Simplified Architecture**: Worker tự quản lý lifecycle, không phụ thuộc Backend availability
5. **Worker Independence**: Worker crash không ảnh hưởng Backend

**Cons Mitigated**:
1. **Audit**: Worker sẽ INSERT vào `audit_events` với actor = service UUID
2. **Validation**: Worker validates domain rules trước khi INSERT
3. **Maintainability**: SQL queries được centralize trong Python repository layer

**Cons of Backend API**:
1. Cần thiết kế 5-10 API endpoints mới (claim job, heartbeat, create revision, bulk insert chunks, update status)
2. Backend trở thành bottleneck cho bulk operations
3. Atomic operations phức tạp qua REST
4. Increased latency (network roundtrip mỗi operation)

## Decision 4: Publication Workflow

### Xác nhận từ Source Code

**File**: `backend/src/main/java/vn/edu/utc/rag/service/ingestion/DocumentService.java` (line 335-337)
```java
e.setStatus("PUBLISHED");
e.setSourceVerified(true);
e.setReviewedBy((UUID) parameters.get("u"));
```

**File**: `backend/src/main/java/vn/edu/utc/rag/persistence/repository/query/ChatQueryRepository.java` (line 26-27)
```sql
WHERE r.status='PUBLISHED' AND r.source_verified AND r.revoked_at IS NULL
```

**Phân tích**:
- Backend yêu cầu STAFF_REVIEWER role để publish
- Backend set `source_verified=true` khi publish
- RAG query bắt buộc cả 3 điều kiện: PUBLISHED + source_verified + NOT revoked
- Backend không có auto-publish logic

### Decision

**Default Workflow**:

```
Worker: INDEXING → PENDING
             ↓
    (wait for reviewer)
             ↓
Reviewer: PENDING → PUBLISHED + source_verified=true
```

**Permissions**:
- Worker: Có quyền update `INDEXING → PENDING` (via PostgreSQL direct)
- Worker: KHÔNG có quyền set `source_verified=true`
- Worker: KHÔNG có quyền update `PENDING → PUBLISHED`
- Reviewer (STAFF_REVIEWER): Có quyền publish và verify
- Reviewer: Có quyền revoke

**Source Verification**:
- `source_verified` chỉ được set bởi reviewer trong Backend
- Worker không bao giờ set flag này
- Ensures human verification cho compliance

**Xuất hiện trong Chatbot**:
- Điều kiện: `status='PUBLISHED' AND source_verified=true AND revoked_at IS NULL`
- Sau khi reviewer approve: Tài liệu xuất hiện ngay lập tức
- Nếu không approve: Tài liệu ở PENDING, không xuất hiện

**Keeping Old Revisions**:
- Khi publish revision mới: Backend set revision cũ `PUBLISHED → ARCHIVED`
- ARCHIVED revisions không xuất hiện trong RAG (status != 'PUBLISHED')
- ARCHIVED revisions giữ lại để audit trail

### Stakeholder Confirmation Required

**Question 1**: Có cho phép auto-publish cho trusted sources không?
- Ví dụ: Trang chính thức của UTC (utc.edu.vn/tuyen-sinh) được auto-verify
- Implementation: Thêm `auto_publish` flag trong `crawl_sources`
- Worker logic: Nếu `auto_publish=true` thì tạo với status='PENDING' và gọi Backend API để auto-approve

**Question 2**: Thời gian chấp nhận được từ đồng bộ đến xuất hiện trong chatbot?
- Nếu cần < 5 phút: Phải implement auto-publish cho trusted sources
- Nếu chấp nhận 1-24h: Reviewer manual approval là đủ
- Ảnh hưởng: Quyết định có cần implement auto-publish flow

**Question 3**: Ai là reviewer và bandwidth của họ?
- Nếu 1 reviewer, 100+ docs/week: Cần prioritization và notification system
- Nếu team reviewer: Cần assignment và SLA tracking

**Phân loại**: 
- Workflow: **Đã được source code xác nhận**
- Auto-publish: **Cần stakeholder quyết định**

### Xác nhận từ Source Code

**Phân tích**:
- Backend hash PDF bytes (raw binary)

- Pipeline key hard-coded "pdf-v1"
- Embedding model từ config: `${app.ollama.embedding-model}`

### Decision

**Hash Strategy by Content Type**:

| Content Type | Hash Input | Rationale |
|-------------|------------|-----------|
| PDF | Extracted text | Same PDF binary với metadata khác = same content |
| HTML | Cleaned text | Ignore HTML formatting changes, focus on content |
| DOCX | Extracted text | Same as PDF reasoning |

**Implementation**:

```python
def compute_content_hash(content_type: str, raw_bytes: bytes) -> str:
    """Compute SHA-256 hash of extracted text content."""
    if content_type == 'application/pdf':
        # Extract text using PyPDF2 or pdfplumber
        text = extract_pdf_text(raw_bytes)
    elif content_type == 'text/html':
        # Parse HTML, extract text, strip whitespace
        from bs4 import BeautifulSoup
        soup = BeautifulSoup(raw_bytes, 'html.parser')
        # Remove script, style tags
        for tag in soup(['script', 'style', 'nav', 'footer']):
            tag.decompose()
        text = soup.get_text(separator='\n', strip=True)
        # Normalize whitespace
        text = '\n'.join(line.strip() for line in text.split('\n') if line.strip())
    elif content_type == 'application/vnd.openxmlformats-officedocument.wordprocessingml.document':
        # Extract text using python-docx
        text = extract_docx_text(raw_bytes)
    else:
        raise ValueError(f"Unsupported content type: {content_type}")
    
    # Hash the extracted text
    return hashlib.sha256(text.encode('utf-8')).hexdigest()
```

**Pipeline Key Versioning**:
- `html-v1`: BeautifulSoup extraction, current chunking logic
- `pdf-v1`: Current PDF extraction (đã tồn tại)
- `docx-v1`: python-docx extraction

**Khi thay đổi pipeline**: Increment version (html-v1 → html-v2)
- UNIQUE constraint cho phép cùng content_hash nhưng khác pipeline_key
- Có thể reprocess documents với logic mới

**Embedding Model Versioning**:
- Lấy từ config: `nomic-embed-text:latest`
- UNIQUE constraint cho phép re-embed với model mới
- **Lưu ý**: Re-embed toàn bộ corpus rất tốn tài nguyên

**Incremental Sync Logic**:

```python
def sync_document(url: str, content: bytes, content_type: str) -> int:
    """
    Returns: revision_id
    Skip embedding if content unchanged.
    """
    # 1. Get or create knowledge_document
    doc = db.query_one("""
        SELECT id FROM knowledge_documents WHERE canonical_url = :url
    """, url=url)
    
    if not doc:
        doc_id = db.execute("""
            INSERT INTO knowledge_documents (canonical_url, crawl_source_id)
            VALUES (:url, :source_id)
            RETURNING id
        """, ...)
    else:
        doc_id = doc['id']
    
    # 2. Compute hash of extracted text
    content_hash = compute_content_hash(content_type, content)
    
    # 3. Check if revision exists
    existing = db.query_one("""
        SELECT id, status FROM document_revisions
        WHERE document_id = :doc_id
          AND content_hash = :hash
          AND pipeline_key = :pipeline
          AND embedding_model = :model
    """, doc_id=doc_id, hash=content_hash, pipeline='html-v1', model=EMBEDDING_MODEL)
    
    if existing:
        if existing['status'] in ('PENDING', 'PUBLISHED', 'ARCHIVED'):
            # Content unchanged, skip
            logger.info(f"Document {url} unchanged, revision {existing['id']}")
            return existing['id']
        elif existing['status'] == 'INDEXING':
            # Resume from crash
            return resume_indexing(existing['id'], content, content_type)
    
    # 4. Content changed or new, create revision and embed
    revision_id = create_revision_and_embed(doc_id, url, content, content_hash, ...)
    return revision_id
```

**Model Change Policy** (cần stakeholder decision):
- Option A: Manual re-embed (admin triggers batch job)
- Option B: Auto re-embed top N high-traffic documents
- Option C: Lazy re-embed (on document update)

**Phân loại**: 
- Hash strategy: **Đề xuất kỹ thuật**
- Model change policy: **Cần stakeholder quyết định**

## Decision 6: Source Discovery và Deletion

### Decision

**Crawl Source Configuration**:

```python
# Database schema extension needed (see migration below)
class CrawlSource:
    base_url: str           # "https://utc.edu.vn"
    sitemap_url: str | None # "https://utc.edu.vn/sitemap.xml"
    robots_txt_url: str     # Auto: base_url + "/robots.txt"
    allowed_path_patterns: list[str]  # ["/tuyen-sinh/*", "/dao-tao/*"]
    excluded_path_patterns: list[str] # ["/admin/*", "/wp-admin/*"]
    rate_limit_seconds: float         # 2.0 = max 1 request per 2 seconds
    enabled: bool
```

**Discovery Strategy**:

```python
def discover_urls(source: CrawlSource) -> list[str]:
    """
    1. Parse sitemap.xml if exists
    2. Follow sitemap index if applicable
    3. Filter by allowed/excluded patterns
    4. Respect robots.txt
    5. Return deduplicated URLs
    """
    urls = set()
    
    # Step 1: Sitemap
    if source.sitemap_url:
        sitemap_urls = parse_sitemap(source.sitemap_url)
        urls.update(sitemap_urls)
    
    # Step 2: Robots.txt (for Crawl-delay)
    robots = parse_robots_txt(source.robots_txt_url)
    crawl_delay = robots.get_crawl_delay('*') or source.rate_limit_seconds
    
    # Step 3: Filter
    filtered = []
    for url in urls:
        path = urlparse(url).path
        if any(fnmatch(path, pattern) for pattern in source.allowed_path_patterns):
            if not any(fnmatch(path, pattern) for pattern in source.excluded_path_patterns):
                filtered.append(url)
    
    return filtered
```

**Deletion Detection**:

```python
def detect_deleted_documents(source_id: int, discovered_urls: set[str]):
    """
    Compare discovered URLs with existing documents.
    Mark as deleted if:
    1. URL not in sitemap
    2. URL returns 404/410 on fetch
    3. Has not been updated in > 90 days (grace period)
    """
    existing = db.query("""
        SELECT kd.id, kd.canonical_url, MAX(dr.updated_at) as last_updated
        FROM knowledge_documents kd
        JOIN document_revisions dr ON dr.document_id = kd.id
        WHERE kd.crawl_source_id = :source_id
          AND dr.status IN ('PUBLISHED', 'PENDING')
        GROUP BY kd.id
    """, source_id=source_id)
    
    for doc in existing:
        url = doc['canonical_url']
        if url not in discovered_urls:
            # Double-check: fetch URL
            try:
                response = requests.head(url, timeout=10, allow_redirects=True)
                if response.status_code in (404, 410):
                    # Confirm deleted
                    # Do NOT auto-revoke, create alert for reviewer
                    create_deletion_alert(doc['id'], url, "HTTP 404/410")
                elif response.status_code == 200:
                    # Still exists but not in sitemap
                    # Maybe sitemap incomplete, keep document
                    logger.warning(f"Document {url} not in sitemap but still accessible")
            except requests.RequestException as e:
                # Network error, don't assume deleted
                logger.error(f"Cannot verify deletion of {url}: {e}")
```

**Rationale**:

### Phase 4: Scheduler (2 days)

**Scheduler Implementation**:

```python
# tools/src/scheduler.py
import os
import requests
from datetime import datetime

def create_jobs():
    """Run every 6 hours via cron"""
    backend_url = os.getenv('BACKEND_URL')
    service_token = os.getenv('SERVICE_TOKEN')
    
    # Get enabled sources
    response = requests.get(
        f"{backend_url}/api/v1/ops/crawl-sources",
        headers={'Authorization': f'Bearer {service_token}'}
    )
    sources = response.json()['content']
    
    # Create job for each enabled source
    for source in sources:
        if not source['enabled']:
            continue
        
        try:
            response = requests.post(
                f"{backend_url}/api/v1/ops/crawl-jobs",
                json={'source_id': source['id']},
                headers={'Authorization': f'Bearer {service_token}'}
            )
            result = response.json()
            print(f"[{datetime.now()}] Source {source['id']}: {'reused' if result['reused'] else 'created'} job {result['job']['id']}")
        except Exception as e:
            print(f"[{datetime.now()}] ERROR creating job for source {source['id']}: {e}")

if __name__ == '__main__':
    create_jobs()
```
