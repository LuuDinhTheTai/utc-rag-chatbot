# Database initialization

Schema PostgreSQL 17 + pgvector theo [ERD v2](https://docs.google.com/document/d/1kbIAin0fkSU_GHSKbgv844z5YnWNPqhKnPp23NAzFNc/edit?tab=t.c7z7a746a2sk), gồm 48 bảng. Không seed dữ liệu.

- `init/001-enable-vector.sql`: bật extension vector, giữ nguyên từ scaffold.
- `init/002-schema.sql`: tạo bảng, PK/UK/FK, khóa ngoại ghép và indexes FK.
- `tests/verify-schema.sql`: kiểm tra các ràng buộc bằng fixtures trong transaction rollback.

## Volume mới

```powershell
docker compose up -d database
```

PostgreSQL tự chạy các file trong `init/` theo thứ tự tên khi volume rỗng.
Compose vẫn có đúng 5 services; không có migration service mới.

## Volume đã tồn tại, chưa có bảng nghiệp vụ

Không cần xóa volume. Kiểm tra database trước khi áp dụng:

```powershell
'SELECT tablename FROM pg_tables WHERE schemaname = ''public'';' | docker compose exec -T database sh -c 'psql -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" -d "$POSTGRES_DB"'
Get-Content -Raw database/init/002-schema.sql | docker compose exec -T database sh -c 'psql -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" -d "$POSTGRES_DB"'
```

Script chạy một lần, toàn bộ DDL trong transaction. Nếu bảng đã tồn tại hoặc có
lỗi, script dừng và rollback, không tự bỏ qua schema lệch. Không chạy lại sau khi
đã init thành công; các thay đổi tiếp theo cần migration riêng. Không dùng `down -v`.

## Kiểm tra

```powershell
Get-Content -Raw database/tests/verify-schema.sql | docker compose exec -T database sh -c 'psql -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" -d "$POSTGRES_DB"'
docker compose ps database
```

Tests cần các ID âm -9001/-9002 và UUID 00000000-0000-0000-0000-000000000001
đến 00000000-0000-0000-0000-000000000005 chưa được dùng. Fixtures chỉ tồn tại
trong transaction kiểm tra, không thay đổi sequence identity hoặc lưu dữ liệu mẫu.

## Quy ước triển khai từ ERD

- Cột có ghi `NULL` cho phép null; các cột khác là `NOT NULL`.
- Giữ nguyên tên cột và kiểu dữ liệu, không tự định nghĩa enum/status hoặc công thức.
- PK số tên `id` dùng `GENERATED BY DEFAULT AS IDENTITY`; PK UUID tên `id`
  mặc định `gen_random_uuid()` tích hợp PostgreSQL. `answer_id` do bên gọi cung cấp.
- Không tự mặc định timestamp/status/config; bên ghi phải cung cấp giá trị.
- PK ghép giữ nguyên. `UNIQUE NULLS NOT DISTINCT` áp dụng cho role assignments
  và admission cutoffs theo ghi chú ERD.
- Khóa ngoại ghép bảo đảm admission options cùng cycle version; cutoffs có tổ hợp
  hợp lệ; personality answers/attempts/profile cùng questionnaire version.
  FK cutoff ghép dùng MATCH SIMPLE để combination_id NULL biểu diễn điểm chung.
- `schedule_events` phải có đúng một trong hai parent FK.
- Chỉ hai quan hệ được ERD chỉ định dùng `ON DELETE SET NULL`:
  feedback → message và citation → chunk. Các quan hệ khác giữ `NO ACTION`;
  không tự suy diễn cascade từ nét Mermaid.
- `document_chunks.embedding` là `vector(768)`. Chưa thêm HNSW/IVFFlat vì ERD
  chưa quy định distance metric hay workload. Index hiện có phục vụ PK/UK/FK.
- Chỉ tạo cấu trúc database; chưa triển khai authentication, API, RAG hay crawler.
